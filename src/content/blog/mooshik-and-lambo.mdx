## The Mount and the Memory

First, a small detour into the names, because anyone who knows me knows I cannot name a software project without a cultural nod or a bit of mythic wordplay.

In Hindu tradition, **Lambodaran** (an epithet of Ganesha) is the deity of intellect, vast wisdom, memory, and the remover of obstacles. His faithful vahana—the mount that carries him into the mortal world—is **Mooshik**, the mouse. 

The Sanskrit root of Mooshik is *mus*, which literally means *to extract, gather, or steal away*. 

```
┌────────────────────────────────────────────────────────┐
│                        LAMBO                           │
│     (Intellect · Structural Graph Memory · Rules)      │
└──────────────────────────┬─────────────────────────────┘
                           │ embedded in-process
┌──────────────────────────▼─────────────────────────────┐
│                       MOOSHIK                          │
│     (The Mount · Ambient Workspace Watcher · TUI)      │
└────────────────────────────────────────────────────────┘
```

That distinction is the core architectural philosophy of the entire project:
- **Lambo** is the intellect and long-term graph memory. It doesn't chat with you, it doesn't open windows; it structures concepts, computes graph blast radius, and decides what is truly load-bearing.
- **Mooshik** is the mount. It sits beside your editor in a terminal pane, quietly extracts and gathers context from your active workspace, and carries Lambo's memory into real-time action.

## Why Vector Dumps Are Not Memory (Enter Lambo)

Most people hear "AI memory" and think of a basic vector database: chunk some text, throw it into an embedding store, and do cosine similarity search when a prompt comes in.

If you have tried building serious multi-agent systems with flat RAG, you know why this fails:
1. **Agent declarations are noisy:** An agent running a loop might write fifty mundane log entries. In a flat store, those fifty entries drown out the single critical architectural decision made two weeks ago.
2. **Similarity is not relevance:** "What will break if I modify this table?" cannot be answered by cosine distance. It requires structural dependency traversal.
3. **Flapping concepts cause havoc:** An agent claiming a temporary workaround shouldn't suddenly become canonical truth across your entire team.

In Lambo, **importance is not declared by an agent; it is earned through structural evidence over time.**

Lambo models memory as a directed property graph of entities, observations, and constraints. On a background daemon loop that no agent can directly call or manipulate, Lambo continuously scores every concept in the graph:

```text
Score(c) = 0.25*R + 0.20*F + 0.20*A + 0.35*D + EdgeBonuses + RecurrenceBonus
```

We factor in Recency (`R`), Frequency (`F`), Session Activity (`A`), and Graph Density (`D`). Crucially, raw assertion edges (`Derives`) contribute exactly zero bonus points. An agent can assert an opinion a thousand times; its score won't budge.

To become permanent, a concept must pass through **three strict promotion gates**:
1. **Candidate:** Must survive 3 garbage collection sweeps and score strictly above the 90th percentile of its non-canonical peers.
2. **Venerable:** Must have at least 3 inbound structural edges from distinct interactions, spanning at least 30% of the session's temporal timeline (bursts within 60 seconds are ignored).
3. **Canonical:** Must achieve a calculated **blast radius** strictly greater than 5 and clear a 300-second cooldown to prevent flapping.

When Mooshik or an agent performs a `recall`, Lambo combines `0.5 * daemon_score + 0.5 * query_relevance`. This means concepts reached by pure graph traversal surface on their structural weight alone—answering *"what rests on this"* rather than merely *"what text looks like this"*.

## Mooshik: The Ambient Cowork Partner

If Lambo is the memory engine, **Mooshik** is the companion that makes it feel alive.

I wanted Mooshik to be **ambient** and **local-first**. It doesn't force you into a bloated browser tab or a heavy Electron wrapper. It runs right in your terminal beside your Neovim, Helix, or VS Code terminal pane:

```bash
mooshik tui
```

```

├──────────────────────────┬───────────────────────────────────────────────┤
│ Active Workspace: ~/work │  Today's Focus:                               │
```

Mooshik links Lambo directly in **Rust**, providing blazing performance, rock-solid concurrency, and instant startup times.

### Flexible Postures: Local Offline vs. Cloud Shared

Not everyone wants their workspace context leaving their laptop, and not everyone works on just a single machine. Mooshik solves this by offering two clear deployment postures out of the box:

1. **Local Posture (Zero Cloud / Offline):**
   - **Database:** Local SQLite (`~/.mooshik/mooshik.db`).
   - **Embedder:** Local BGE-M3 running in-process.
   - **Inference:** Local OpenAI-compatible endpoint (Ollama, llama-server, vLLM).
   - *Zero bytes leave your machine.*

2. **Shared Posture (Google Cloud / Team & Multi-Device):**
   - **Database:** Google Cloud SQL PostgreSQL with `pgvector`.
   - **Embedder:** Google Vertex AI `gemini-embedding-001` (1536-dim).
   - **Companion Inference:** Google Vertex AI `gemini-3.7-flash` at `global`.
   - *Your desktop, your laptop, and your cloud batch jobs share one synchronized, continuous memory graph.*

## Google Ecosystem & Agent Architecture

For the All Things Agentic Hackathon, we leaned heavily into Google's premier agent frameworks and infrastructure:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                SURFACES                                 │
│             Terminal Pane (mooshik tui)  ·  CLI Commands                │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
┌────────────────────────────────────▼────────────────────────────────────┐
│                         MOOSHIK RUNTIME (Rust)                          │
│   Event & Intent Router · Companion Loop · Workspace Watcher · Sandbox  │
└──────────────┬───────────────────────────────────────────┬──────────────┘
               │                                           │
┌──────────────▼─────────────┐              ┌──────────────▼──────────────┐
│  LAMBO IN-PROCESS (Rust)   │              │  GOOGLE CLOUD & AGENT FRAME │
│ Concept Graph · WriteLane  │              │  Vertex AI Gemini 3.7 Flash │
│ Canonization · Blast Radius│              │  Google ADK Ingester & MCP  │
└──────────────┬─────────────┘              │  Cloud SQL Postgres+pgvector│
               │                            └──────────────┬──────────────┘
               └───────────────────────────────────────────┘
```

1. **Gemini 3.7 Flash via Vertex AI:** Fast streaming, large reasoning context, and reliable tool calling in the companion loop.
2. **Google Agent Development Kit (ADK):** 
   - The **Bootstrap Ingester** uses Google ADK to parse multi-year repository histories, RFCs, and incident reports into structured graph entities.
   - The **Artifacts MCP Server** uses ADK `LlmAgent` with Gemini 3.7 Flash to extract typed concepts and architecture diagrams from screenshots and audio recordings over stdio.
3. **Workspace Polling Watcher:** Watches your file edits and git commits (capturing author timestamps and commit metadata) without mindlessly dumping raw source code into memory.
4. **Tool Permission Gates & Vault:** Secrets live in an AES-256 encrypted local vault (`~/.mooshik/vault`). Tool outputs and model prompts pass through automated egress redaction filters. Memory operations are permitted by default; script execution in the scratch sandbox prompts for explicit user grants.

## 899 Tests and Zero-Credential Reproducibility

If there is one thing I take immense pride in as an engineer and technical writer, it is **reproducibility**.

Hackathon judges often receive projects that require four hours of cloud provisioning, expired API keys, and flaky web endpoints. We took the opposite approach: **every single test runs completely offline without any API keys, credentials, or databases.**

- **Rust Core:** 674 unit and integration tests covering the memory seam, companion loop cancellation, workspace watcher, MCP host, TUI view model, and permissions.
- **Python Services:** 225 pytest tests covering the Google ADK ingester, measurement harness, News MCP server, Artifacts MCP server, and Coder delegation server.
- **Total:** **899 offline tests**, all passing in GitHub Actions CI on every commit.

You can clone the repo, run `cargo test`, and verify the entire system in seconds.
